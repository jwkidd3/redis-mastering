Day 3 - Afternoon Session

RDB Snapshots

What: Point-in-time binary snapshots at configured intervals
Strengths: Compact files, fast restart, low ongoing overhead — ideal for backups & DR
Trade-off: Data between snapshots can be lost on crash
# Runtime: configure snapshot thresholds CONFIG SET save "900 1 300 10 60 10000" # Save after: 900s if >=1 change, 300s if >=10, 60s if >=10000 # Trigger a non-blocking snapshot BGSAVE # Check last successful save LASTSAVE INFO persistence
Insurance example: Policy-quote cache — 60/10000 catches renewal-cycle bursts, 900/1 guarantees at least one snapshot overnight.

AOF (Append-Only File)

What: Log of every write command (replayable)
Strengths: Near-zero data loss with everysec; audit trail; human-readable
Trade-off: File grows; requires periodic rewrite
# Enable AOF at runtime CONFIG SET appendonly yes CONFIG SET appendfsync everysec # balanced durability/perf CONFIG SET aof-use-rdb-preamble yes # hybrid RDB+AOF # Compact the log BGREWRITEAOF # Check AOF status INFO persistence
Best practice: Use hybrid persistence (RDB + AOF with preamble) for business-critical insurance workloads — fast restart from RDB, minimal data loss from AOF.

Memory & Eviction Policies

# Set maxmemory and eviction policy CONFIG SET maxmemory 2gb CONFIG SET maxmemory-policy allkeys-lru INFO memory
PolicyBehaviorTypical Use
noevictionErrors when fullPersistent-only stores
allkeys-lruEvict any LRU keyGeneral caching
volatile-lruEvict TTL keys, LRUMixed cache + persistent
volatile-ttlEvict shortest TTLTime-sensitive data
Insurance example: Quote cache with 24h TTL — volatile-lru aggressively evicts stale quotes while preserving long-lived policy reference data.

Production Security Hardening

# Authentication CONFIG SET requirepass "strong_password_here" # ACLs (Redis 6+) — per-user credentials ACL SETUSER claims_svc on >svc_pwd ~claim:* +@read +hset # Disable or rename dangerous commands CONFIG SET rename-command FLUSHALL "" CONFIG SET rename-command CONFIG "CONFIG_abc123" # Bind to private interfaces — never 0.0.0.0 in production CONFIG SET bind "127.0.0.1 192.168.1.100" CONFIG SET maxclients 10000 # Persist runtime changes to redis.conf CONFIG REWRITE
Defense in depth: Combine requirepass/ACLs, renamed dangerous commands, bound interfaces, firewall rules, and TLS for insurance workloads handling PII/PHI.

Backup Automation

#!/bin/bash # Daily backup script DATE=$(date +%Y%m%d_%H%M) BACKUP_DIR="/backups/redis/$DATE" mkdir -p $BACKUP_DIR redis-cli BGSAVE cp /data/business-data.rdb $BACKUP_DIR/ gzip $BACKUP_DIR/business-data.rdb # 30-day retention find /backups/redis -mtime +30 -delete
RDB recovery: Stop Redis, replace RDB, restart
AOF recovery: Stop Redis, repair/replace AOF, restart
Cross-region: Replicate compressed backups to a secondary region
Critical: Untested backups are not backups. Schedule restore drills.
